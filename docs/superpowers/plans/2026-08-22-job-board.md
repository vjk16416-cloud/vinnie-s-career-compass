# CareerOS Job Board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a live, preference-aware Job Board that retrieves UK and global remote vacancies, ranks them for discovery, and hands selected roles into the existing evidence-backed Job Scan workflow.

**Architecture:** Add a server-side provider boundary for Arbeitnow UK and Remotive, normalise both into a canonical discovered-job model, deduplicate and rank results using persisted search preferences plus approved Career Profile keywords, then render them in a new `/jobs` route. Formal compatibility remains in the existing `runScan()` pipeline.

**Tech Stack:** TanStack Start, React, TypeScript, Zod, existing CareerOS cloud snapshot persistence, Vitest / Testing Library, Cloudflare production build.

**Spec:** `docs/superpowers/specs/2026-08-22-job-board-design.md`

## Global Constraints

- Preserve the existing evidence policy and `runScan()` authority.
- Do not add a new database table for v1.
- Do not auto-create applications or auto-apply.
- Do not scrape LinkedIn or Indeed.
- Visa sponsorship is displayed only when provider data explicitly states it.
- Remotive vacancies must identify Remotive as source and link to the Remotive vacancy URL.
- Provider fetching must require the authorised CareerOS user.
- Existing cloud snapshots must remain valid.
